## [1.0.0]

Ground-up rewrite and rename from **`pocketbase-zod-generator`** to **`pb-ts-zod`** — the first
release under the new name.

### Added

- **Zod 4 output by default**, with a `--zod 3` compatibility flag for legacy projects.
- **`node:sqlite` reader** — read collections directly from `pb_data/data.db` with zero native
  dependencies (Node ≥ 22.5). Offline, no server, no credentials.
- **Typed `expand`** (Zod 4): each relation's expand key is typed as the target's Response schema
  (object for single, array for multi), plus reverse **back-relations** `{collection}_via_{field}`
  (arrays, or a single object when the source relation is uniquely indexed — detected from the
  collection's `indexes`). Circular and self-referential relations use Zod 4 recursive getters.
  `--no-expand` and `--no-back-relations` fall back to / trim this; `--zod 3` uses the generic
  `z.record` envelope.
- **Real validators**, opt out with `--no-validators`:
  - `min`/`max`/`.regex(...)` for text, `.int()`/`min`/`max` for numbers
  - `.max(n)` for multi-value arrays, and `.min(n)` from `minSelect` on **required** relations
  - email/url domain restrictions (`onlyDomains`/`exceptDomains`) → `.refine(...)`
  - custom record ids — a non-default id length/pattern emits explicit `.length()`/`.regex()`
- **`geoPoint` field support** (PocketBase v0.27+) → `{ lon, lat }`.
- **Record vs Response schemas**: system fields (`id`, `created`, `updated`, auth fields) are read
  from the schema and placed only on the `*ResponseSchema`; hidden fields (`password`, `tokenKey`)
  are excluded from both. Server-filled fields — text fields with an `autogeneratePattern` — are
  `.optional()` in the Record (create) schema even when `required`.
- **Typed registries**: `Collections` enum, `CollectionRecords`, `CollectionResponses`, and a
  runtime `Schemas` map.
- **`--split` mode**: one module per collection plus a shared aliases module and an index.
- **A real test suite.** Unit tests (Vitest) that compile the emitted Zod 4 source and execute it
  against sample records, plus an end-to-end round-trip against a real PocketBase covering
  self-referential relations, a second auth collection, an autogenerated slug, a custom id,
  `minSelect`, a unique-indexed 1:1 (single back-relation), a `LEFT JOIN`+`count` view,
  domain-restricted email/url, and unicode/boundary/deep-json seeds. Live `?expand=` payloads
  (single, multi, nested, and back-relations) are validated against the generated typed expand.
  Biome lint/format, TypeScript typecheck, and a tsdown build round out the gate.

### Changed

Relative to `pocketbase-zod-generator`:

- **Correct PocketBase v0.23+ authentication**: superuser auth via the `_superusers` collection
  (the removed `/api/admins/auth-with-password` endpoint is kept only as a legacy fallback).
- **Correct schema model**: reads the v0.23+ `fields` array with flattened options, falling back to
  the legacy `schema`/`options` shape.
- **PB-accurate dates**: `IsoDateString` accepts PocketBase's space-separated datetimes and the `""`
  empty sentinel — where `z.iso.datetime()` would reject real API responses.
- **Empty-value correctness**: optional `email`/`url`/single-`select` fields emit
  `.or(z.literal(""))` to accept PocketBase's empty sentinel.
- **Hidden fields are excluded** from both Record and Response schemas — they are never serialized
  by the API.
- **Text `min`/`max` of `0` mean "unbounded"** (the Go int zero value), so no spurious `.min(0)` or
  `.length(0)` is emitted for text and id fields. Number `min`/`max` are nullable pointers, so `0`
  there remains a real bound.
- Dropped the `cross-fetch`, `form-data`, `sqlite`, and `sqlite3` dependencies (global `fetch` +
  `node:sqlite`). The only runtime dependency is `commander`.

### Migration from `pocketbase-zod-generator`

- Binary renamed to `pb-ts-zod`. CLI flags remain compatible.
- Generated output targets Zod 4 by default — pass `--zod 3` to keep the old idioms.
- See the [migration table](./README.md#migrating-from-pocketbase-zod-generator) in the README.
